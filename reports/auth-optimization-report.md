# 登录注册系统优化与测试报告

- 执行日期：2026-10-08
- 系统：Spring Boot 4.1 + 原生 HTML/JS + MySQL 8（服务 :8080）
- 范围：认证链路（登录 / 注册 / 找回密码 / 恢复令牌 / 邮件验证码 / 账号锁定），不含数据库结构与基础设施变更
- 改动前备份：`reports/backups/auth-opt/`（5 个 Java 文件 + auth.js + 2 个 HTML）
- 测试方式：PowerShell `Invoke-RestMethod` 发 `application/json`（与前端 fetch 完全一致的请求形态）+ MySQL 直查取证；测试数据用后即清

## 一、优化项清单

### 后端（5 项健壮性/安全增强 + 1 项测试中发现的真实缺陷修复）

| # | 文件 | 问题 | 修复 |
|---|---|---|---|
| 1 | AuthController.java | 注册 DTO 无长度上限，仅 `@NotBlank`/密码 min=8，超长字段可直达 DB 层 | 全字段补 `@Size`（与 DB 列对齐：用户名≤30、密码 8-64、姓名≤50、身份证≤18、手机≤11、邮箱≤100、验证码≤6），登录 DTO 同步加上限 |
| 2 | UserService.java / ValidationUtils.java | **前端有用户名规则 `字母开头4-30位`，后端完全没有**，可直接调 API 绕过注册任意用户名（中文/空格/纯数字，纯数字还会与"手机号登录"歧义） | ValidationUtils 新增 `isUsername`（`^[A-Za-z][A-Za-z0-9_]{3,29}$`），register 先校验格式再查重；密码上限 64（防超长输入放大 BCrypt 开销） |
| 3 | UserService.java | 登录时序侧信道：账号不存在时直接返回、不执行 BCrypt，可按响应耗时枚举有效账号 | 固定 dummy BCrypt 哈希，用户不存在时也执行一次 `matches` 拉平时延；响应文案本就统一为"账号或密码错误" |
| 4 | UserService.java / UserRepository.java | 通过邮箱/恢复令牌重置密码、登录态改密后，历史失败计数与 30 分钟锁定仍然生效（证明身份后无法用自己的新密码登录） | 新增 `unlock(id)`，三条改密成功路径均清除 `login_fail_count` 与 `lock_until`；锁定提示改为显示剩余分钟 |
| 5 | UserService.java | 找回密码接口对未注册邮箱返 404"该邮箱未注册"，可枚举平台注册邮箱 | 非公共邮箱未注册时返回与成功一致的 `{sent:true}` 但不发信、不落库；前端文案改"若该邮箱已注册，验证码将发送至该邮箱"。公共邮箱仍保留"用户名+邮箱双匹配"强校验 |
| 6 | **EmailService.java（P1，测试中发现）** | **邮件发送 60 秒间隔频控静默失效**：`queryForList` 取出的 `created_at` 在 MySQL Connector/J 8 下映射为 `LocalDateTime`，代码只识别 `java.sql.Timestamp`，`instanceof` 恒 false，间隔检查被整体跳过（实测 55 秒内连收两封邮件） | 改用 JDBC 4.2 `rs.getObject("created_at", LocalDateTime.class)` 显式取值，不依赖驱动默认映射 |

### B 组 · 账号锁定（6/6 通过）

### E 组 · 找回密码防枚举与公共邮箱（4/4 通过）

### G 组 · 邮件频控缺陷（修复前取证 + 修复后复测）

- 修复前：预置 30 秒前记录后请求发码 → 200 放行，实际新增邮件记录（两条间隔仅 55 秒），**缺陷实锤**
- 修复后：预置 20 秒前记录 → **429「发送过于频繁，请40秒后再试」，邮件记录数不变（未发信）**

## 五、结论与遗留建议

**结论**：认证链路 6 项代码优化全部落地，38 项接口断言 + 6 项 DB 取证全部通过，编译一次通过、服务正常运行、测试数据零残留。本轮额外发现并修复了 1 个已存在的 P1 缺陷（邮件频控因 JDBC 类型映射静默失效，存在邮件轰炸/配额滥用风险）。

**遗留建议（本轮按范围约束未动）**：

1. 登录仅按账号维度锁定，未做 IP 维度限流（NAT 误伤与单 IP 撞库需权衡，建议后续按"同 IP 失败 N 个不同账号"做宽松阈值）。
2. `@CrossOrigin` 当前无来源白名单，上线前应限定可信域名。
3. JWT 密钥本地仍为随机生成（重启即失效），生产部署需注入固定 `APP_JWT_SECRET`（既有遗留，application.yml 已支持环境变量）。
4. 注册成功后自动登录依赖第二次登录调用，如极端情况下登录失败会出现"已注册但未进入系统"，建议后续改为注册接口直接签发 token（契约级变更，未在本轮范围）。
